# 步驟四: 發佈

使用者說「幫我發 PR」、「可以發佈了」時執行。

## 步驟

1. 跟使用者確認要不要拿掉 `draft: true`。拿掉之後，PR 合併文章就會出現在網站上；不拿掉的話，合併後也不會顯示。
2. 回頭補連結: 步驟一找到的舊文章(例如年度購物清單裡寫著「之後會寫開箱文」)，把那句改成連到這篇新文章，例如 `詳細的開箱可以看 [這篇](../../11/<slug>/index.md)`。
   - 如果這篇新文章還是 `draft: true`，提醒使用者這個連結在網站上會點不到。
3. commit 時只加入這篇文章相關的檔案(`index.md`、`res/` 裡的圖片、上面第 2 點改到的舊文章)。工作目錄裡其他未 commit 的修改不要一起加進去；如果同一個檔案裡有使用者自己改的其他內容，先告訴使用者。
4. push branch，開 PR 到 `master`。PR 標題用文章標題，內容簡短說明新增了哪篇文章、改了哪些舊文章。

## 回報

- PR 連結
- 文章目前是不是 draft
- 沒有被加進 PR 的未 commit 修改
