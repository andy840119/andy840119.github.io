# 寫部落格文章

這份文件說明整個流程，每個步驟的細節在各自的檔案裡。
執行某個步驟前，先讀那個步驟的檔案，以及 [style.md](style.md)(寫作風格)。

> 這份文件不限定給哪個 AI 工具使用(Claude、ChatGPT、Copilot... 都可以)，把內容當作指引即可。
> 文中提到的「讀檔」、「看圖片」等步驟，請用該工具能用的方式完成。

## 流程

| 步驟 | 使用者大概會說 | 要做的事 | 細節 |
|---|---|---|---|
| 1. 初始化 | 「我想要寫 xxx 的開箱文」 | 開 branch、建資料夾、建骨架 | [1-init.md](1-init.md) |
| 2. 寫初稿 | 「圖片貼上去了，幫我寫完」 | 看圖、照使用者的補充寫成完整初稿 | [2-draft.md](2-draft.md) |
| 3. 檢查 | 「寫完了，幫我檢查一下」 | 找錯字、不通順、前後矛盾，列出來給使用者確認 | [3-review.md](3-review.md) |
| 4. 發佈 | 「幫我發 PR」 | 拿掉 draft、補舊文章連結、commit、開 PR | [4-publish.md](4-publish.md) |

步驟之間使用者會自己修改文章，每一步開始前都要重新讀一次 `index.md`，以檔案目前的內容為準。

## 所有步驟共通的規則

- **作者自稱一律用「不才」，不要用「我」。**
- **不要捏造**: 價格、日期、數據、規格、個人經驗只能用使用者給的或圖片上看得到的。資訊不足的地方用 `<!-- TODO: ... -->` 標記；從圖片推測、不確定的內容加上 `(待確認)`，並在回報時提醒使用者。
- 文章在發佈前都保持 `draft: true`。
- 不要動使用者沒提到的其他檔案；工作目錄有其他未 commit 的修改時，告訴使用者，但不要幫忙 commit 或丟掉。
- 回報時用條列說明做了什麼、哪些是推測的、哪些需要使用者補，不要把整篇文章貼回對話中。
