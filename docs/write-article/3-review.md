# 步驟三: 檢查

使用者說「寫完了，幫我檢查一下」時執行。這時文章大部分是使用者自己寫的，目標是抓問題，不是重寫。

## 先確認是「檢查」還是「潤稿」

使用者有時會把這兩個詞混著用。如果使用者說的是「潤稿」，先問清楚要哪一種再開始:

- **檢查**: 只抓錯字、不通順、前後矛盾等問題，盡量不動原句。這份文件說的就是這個。
- **潤稿**: 除了上面的問題，還會調整句子讓文章更順，例如重新斷句、補上轉折、整理段落，改動範圍比較大。

使用者說「檢查」、「確認」時，直接當作檢查，不用再問。

## 要不要先問再改

改之前先看文章檔案的 git 狀態(例如 `git status --porcelain <檔案>`、`git stash list`):

- **檔案沒有未 commit 的修改**(使用者已經 commit 或 stash 了): 直接改，不用先問。改錯了使用者可以自己 rollback。改完後照下方「修改後」回報。
- **檔案有未 commit 的修改**: 先列出來，等使用者說「修」、「直接修」再改；使用者也可能只想改其中幾條。

## 原則

- 保留使用者的語氣和口頭禪，不要改成書面語。風格是否正確以 [style.md](style.md) 為準。
- 不確定使用者原意的地方，列成問題問使用者，不要自己猜一個答案改上去。

## 要檢查的項目

1. **錯字**: 同音字(例如「行理」→「行李」、「在打氣」→「再打氣」、「不同測」→「不同側」)、漏字、多字。
2. **語句不通順**: 讀不懂、主詞不清楚、斷句奇怪的句子，給出改寫建議。
3. **語意相反或用錯的詞**: 例如「挖自己埋的坑」其實應該是「填自己挖的坑」。
4. **前後矛盾**: 例如優點寫「走線一次搞定」，內文卻說沒用那個理線槽；或數字前後對不上。
5. **自稱**: 找出漏掉的「我」，改成「不才」(「我去」、「我的乖乖」這類感嘆語除外)。
6. **用詞統一**: 例如「托運 / 託運」混用。
7. **格式**:
   - 標題層級一致(例如 Q&A 都是 `###`)
   - 沒有連續兩個 `.`
   - 圖片說明有接在對應的圖片下面
   - 列表結尾標點一致
8. **連結和圖片**: 文章引用的 `res/` 圖片都存在、舊文章的相對連結路徑正確。
9. **殘留**: 還沒處理的 `<!-- TODO -->`、給 AI 的指示、`(待確認)`。

## 回報格式

- 錯字、不通順: 用表格列出「行號 / 原文 / 建議」
- 語意、前後矛盾、需要使用者決定的地方: 用條列說明原因
- 如果需要先問(檔案有未 commit 的修改)，最後問使用者要不要全部改，或只改其中幾條

## 修改後

- 改完再搜尋一次，確認舊的錯字都不在了
- 回報改了幾處，並特別列出「照自己的推測補上資訊」的地方，請使用者確認
